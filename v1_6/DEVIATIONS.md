## Development after the preregistration hash, before the freeze (design changes)
PREREG.md was not edited. These changes were made while developing on dev data only. Each is hold-only except the waiver.
3. **New hold rules not listed in PREREG.** The preregistration lists the clause-finder fix, the system-tag handling, the waiver and the classifier refit. Development added more hold-only rules, all on dev evidence: (a) a resource-object rule in the instruction check (an order shape plus a file, credential, account, money, message or code noun within the object window); (b) out-of-vocabulary verbs after "please" or "kindly" and in modal frames; (c) hyphen-to-space, verb-verb compound ("brute force the PIN") and verb-article-noun phrase variants sent to the map. These added holds (dev unseen-verb recall 41 to 58 of 60 on the spent v1.5 set, C0). They are in `src_py/instruction_check.py` and `src_py/map_check.py`. One variant (verb plus particle plus article plus noun) was narrowed after it held the Wikipedia quasar page ("gas in the disc").
4. **Waiver changes from the PREREG text.** The how-to test needs at least 30 percent of sentences to open with a command verb (PREREG said "most", which I coded as 50 percent first). The cue list grew after dev showed the waiver lifted about 11 percent of planted injections: any order shape (not only sentence starts) with a resource or action noun in its window (money, card, record, patient, garage, alarm, camera, ...), a fixed list of action verbs at an order start (delete, wipe, install, email, unlock, ...), agent phrases ("before answering", "translator's note", "I need you to", "urgent", "do not tell", ...), and any override or system-tag reason from the instruction check. After these changes the waiver lifted 1.3 percent of dev injected holds in the full-stack dev sample (7 of 520 including classifier lifts).
5. **A second dev pool.** After the preregistration I added 2,363 topical Wikipedia intro pages (banking, payments, email, security, cooking, smart home, robotics, games ... public MediaWiki API; `data/topical_v16.jsonl`) as hard clean pages and planted injections for the dev set and the classifier refit (fit/val split by URL hash). It lowered the refit classifier's false holds on finance and IT pages a little. Classifier threshold 0.55, chosen on validation pages only (cap 3 percent false hold on real clean pages).
6. **Choice rule outcome.** C3 (fixes plus waiver plus refit classifier) passed criteria (a) to (c) (dev lift 1.3 percent; InjecAgent lifted A 0, B 0; 0 new false holds on the old clean pages) and had the fewest false holds on clean dev pages, so v1.6 ships C3. Criterion (a) and the lift rate were only reached after change 4, which means the rule was evaluated after tuning the waiver on the same dev data.
7. **The pool fetch ran after the test set already existed** (its files are dated 07:56 to 07:57 EST; my pool fetch ran after). I did not look at the test set. Both of us sampled public Wikibooks and Wikipedia pages at random, and 15 URLs overlap (see below).
8. **Dev evaluation used a Python emulator** of the gate (`src_py/dev16_lib.py`), which reproduces v1.5 decisions except the Rust-only content layers (3 differences on 360 records). The final configuration was checked through the real Rust stack on a 1,261-record dev sample (`out/dev_gate_run.txt`): Rust and Python map engines agree on all records.
9. **InjecAgent in development.** Used only as a regression guard (count of lifted A and B holds, new C holds) after each change, as the preregistration allows; no number was tuned on it directly, but a failure of the guard (211 new C holds from the first version of the resource-object rule) made me refine that rule. That is a form of tuning against InjecAgent C.
10. **Dry run.** Before the freeze the full runner and scorer were run on the spent v1.5 set (`NYM0_DRY=1`) to check the machinery. Its output (`out/DRY_*`) is dev only.
11. **Rust.** `front/src/pipeline.rs` and `classifier.rs` gained a logged `relax` field (waiver). A non-empty `relax` returns the unchanged result of the earlier hard layers and skips only the classifier, instruction-check and map holds. The map engine and its Rust port are unchanged from v1.5. The clause finder, the how-to test and the waiver decision are in Python, as stated in PREREG.md.
12. **Baselines.** Only v1.5 and v1.4 are rerun as baselines (PREREG R1). v1.1 to v1.3 are not rerun in this build. `baseline_v1_5` shares its files with the v1.5 folder (hard links); its models were checked equal to `models/` and are left out of the full zip to save space (see README).

13. FREEZE.sha256 lists 145 files (code, models, Rust source, data, runner, scorer, dev summaries). SHA256SUMS of the test set was verified (all 18 files OK) after the freeze and before opening.
14. **Converter written after opening.** `src_py/convert_newset_v16.py` was written after the set was opened. It copies test_set.jsonl, adds two fields (`key_verb`, `category`) to the 60 unseen-verb records from `unseen_verb_meta.jsonl`, and checks that every record's id, gold and untrusted_text are byte-identical to the source. It writes `data/new16_all.jsonl` (sha256 4ddaa088...) and `data/NEWSET.json`. It did not change or add any text. The runner and scorer (written and frozen before the opening) read those two files.
15. **Separation check found overlaps** (`data/SEPARATION_CHECK_v16.json`): 15 of 300 test records share a URL and title with dev data and 3 share a text start. The preregistration did not say what to do. The bars were scored on all 300 records. A sensitivity run without the 15 (`src_py/sens_v16.py`, written after scoring, `out/SENSITIVITY_v16.json`) is reported in RESULTS.md. The false-hold count is the same (17) with or without them.
